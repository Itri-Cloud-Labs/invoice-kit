Moroccan paperwork, from a typed object to a PDF.

invoice-kit is a TypeScript library for Node.js. Describe a sale once and get a Facture, a Devis, a Bon de commande, a Bon de livraison, a Bon de retour or a Demande de prix, with the TVA worked out and the ICE, IF and RC printed where an accountant expects them.

One input, six documents

Six factories share one input shape. Invoices, quotes and purchase orders carry prices and totals. Delivery notes, return notes and price requests take the same items and print quantities only: no unit price, no TVA, no bank details.

The arithmetic is already done

            

              Line discounts come off first, then document discounts. What is left is the taxable base. TVA is 20%
              unless you pass another rate, and every figure is rounded to the centime. Change a number and read the
              sheet.
            

            

            

          


          

            
Leave a field out and it leaves the page

            

              Every top-level field is optional. The library prints what you give it and closes the gap around what you
              don't: no placeholder client, no empty bank box. Skip the footer and the title and number take its
              place on the bottom edge.

Seven colour slots

            

              primary paints the issuer name, the table header and the total row. Six more slots cover
              the text on top of it, body text, metadata, section labels, borders and the footer. Give hex values for
              the ones you care about; the rest keep their defaults.
            

            

            

            

          


          

            
Every gap, in points

            

              The roomy layout is the default. Eighteen spacing values can be overridden per render, in PDF points,
              72 to the inch. Six of them are wired up here. In the real renderer, pushing them far enough moves
              sections onto a new page.
            

            

            

          

        

      


      

        

          

            
It refuses bad input by name

            

              Input is validated before any document is built. A mistake comes back as an error that names the field,
              before a single page is drawn. The messages in this table are produced right now, in your browser, by
              the package's own validator.

The parts you would rather not write

          

            

              
Long tables

              
When the item table runs out of page it continues on the next one and prints its header row again. Multi-line footers reserve their own space first.

            

            

              
Logos by URL

              
Put an http or https address in issuer.logo and the renderer fetches it. PNG and JPEG go in as they are. SVG and WEBP are converted to PNG on the way.

            

            

              
Bank details

              
Two shapes, checked by type: a local transfer with bank, holder and RIB, or an international one with SWIFT and IBAN.

            

            

              
Arabic labels

              
locale: "ar-MA" switches titles and labels to Arabic. A DejaVu Sans fallback is embedded in the package; your own fonts can be passed as a path, a Uint8Array or an ArrayBuffer.

            

            

              
Nothing to copy at deploy

              
PDFKit is vendored with its font metrics inside the bundle, so an ESM server build needs no asset files next to it. Node.js 18 or newer.

            

            

              
Tested behaviour

              
A node:test suite covers totals, TVA edge cases, validation, sparse documents, quantity-only normalisation, remote logo formats and pagination.

            

          

        

      


      

        

          

            
Start with one file

            

              Install the package, call a factory, write the PDF. toPDF() also returns the bytes as a
              Uint8Array, so you can send them from a route handler without touching the disk, and
              toJSON() hands back the computed document.
