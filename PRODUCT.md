# Product

## Register

brand

## Users

Developers building billing, ERP, or back-office software for Moroccan businesses, usually on Node.js. They arrive from npm or GitHub while evaluating libraries and want to know two things fast: does the output look like something a client can send, and is the API sane. A second audience is the technical founder or agency lead who will not read the README but will judge the PDF.

## Product Purpose

invoice-kit (`@ic-labs/invoice-kit`, by Itri Cloud Labs) turns one typed object into a Moroccan business document as a PDF: Facture, Devis, Bon de commande, Bon de livraison, Bon de retour, Demande de prix. It calculates line and document discounts, taxable base, TVA and totals, knows MAD, ICE, IF, RC and RIB, validates input, and renders only the fields it is given. The site succeeds when a visitor has seen the real output, changed it with their own hands, and copied the install command.

## Brand Personality

Exact, tactile, sure-handed. The voice is a developer who has also stood at the counter of a papeterie: plain statements, real field names, French document terms left in French. Warm through colour and type, never through jokes at the reader's expense. The one piece of humour is the closing invoice for 0,00 MAD.

## Anti-references

- Dark-mode developer-tool templates with glowing gradients and floating dashboards.
- Fintech navy-and-white with stock invoice mockups in rounded cards.
- Cream editorial pages with an italic display serif and mono labels.
- Zellige patterns, arches, or any other shorthand for "Moroccan".
- Feature-card grids, hero metrics, testimonials, or any claim the repository cannot back.

## Design Principles

1. The document is the star. A real, legible A4 sheet stays on screen and everything else comments on it.
2. Show the library working. Totals, labels and error messages on the page come from the package's own modules, and downloads are PDFs it rendered.
3. Say only what the code does. Planned work is labelled planned; rough edges are not dressed up as features.
4. Stationery, not software chrome. Coloured stock, ink, ruled lines, tick boxes and fill-in blanks instead of cards and glass.
5. One idea per screen, in the reader's own hands: each chapter changes one thing about the sheet.

## Accessibility & Inclusion

WCAG 2.2 AA. Ink-on-stock text stays above 4.5:1 on all six ground colours. Every control is a native input with a visible focus ring and works by keyboard. Motion is decorative only and collapses under `prefers-reduced-motion`. Document type is never signalled by colour alone: tabs and options carry names.
